## 4. 四大知识板块到底在考什么

### 第一类：大模型基础与能力

这一类考的是你到底懂不懂 LLM 本身，而不是只会 SDK 调用。

重点包括：

- Transformer、Token、上下文窗口、采样参数
- 预训练、SFT、RLHF、DPO、对齐
- 模型选型、开源与闭源、云模型与本地模型
- 推理性能、KV Cache、Batch、TTFT、TPS
- 量化、蒸馏、LoRA、PEFT、微调
- 多模态、语音、图像、OCR、代码模型
- 模型服务框架与部署形态，例如 Ollama、llama.cpp、vLLM、Xinference

如果这部分不稳，后面所有工程化话题都会变成“只会背框架名词”。

### 第二类：Java AI 工程与框架集成

这一类考的是你能不能把模型能力真正接入 Java 业务系统。

重点包括：

- 为什么 AI 应用可以选 Java，而不一定非要 Python
- Spring AI、LangChain4j、官方 SDK 的取舍
- 流式输出、SSE、WebSocket、异步任务、并发控制
- Prompt 模板、结构化输出、JSON Schema、对象映射
- Tool Calling、Function Calling、MCP、Chat Memory
- 会话管理、多租户、缓存、重试、超时、限流、降级
- 本地模型接入、模型提供商抽象、配置治理、Secrets 管理

这部分决定你是不是“能落地的人”。

### 第三类：RAG 检索增强

这一类考的是企业知识问答场景的完整工程能力。

重点包括：

- 文档解析、切分、清洗、元数据与增量索引
- Embedding、向量库、混合检索、Rerank、Query Rewrite
- Prompt 组装、拒答、引用可追溯
- 评估闭环、延迟与成本、权限隔离
- Agentic RAG、GraphRAG、Contextual Retrieval 等增强方向

### 第四类：Agent、工作流、评估、安全与运维

这一类考的是你能不能把 AI 应用从 demo 做到生产。

重点包括：

- Workflow 与 Agent 的区别
- Prompt Chaining、Routing、Parallelization、Orchestrator-Workers、Evaluator-Optimizer
- Tool 设计、权限边界、幂等性、失败恢复
- 评估体系、离线评估、在线评估、人工评审、A/B Test
- 可观测性、Tracing、Token 成本、延迟、工具成功率
- Prompt Injection、越权调用、敏感信息泄漏、OWASP GenAI 安全风险
- 灰度发布、回滚、SLA、容量规划、事故处理、合规

这部分最能拉开高级候选人与初级候选人的差距。

## 5. 结合这个项目，你可以怎么答得更像“做过项目”

这份仓库主线能力包含 RAG，同时也提供很多工程锚点，面试时可以借这些代码证明你理解 Java AI 应用工程化。

建议重点结合下面几类代码去表达：

1. 模型接入抽象：maxkb4j-service/maxkb4j-model 下的多模型 Provider，例如 Ollama、Xinference。
2. 工作流编排：maxkb4j-service/maxkb4j-workflow 下的 ChatWorkflowHandler、KnowledgeWorkflowHandler。
3. 任务触发与调度：maxkb4j-service/maxkb4j-trigger 下的 TriggerScheduler、TriggerTaskExecutor、EventTriggerTaskProcessor。
4. 应用启动与部署：maxkb4j-start 下的 Dockerfile、启动模块配置。
5. Maven 多模块拆分：service、service-api、common、start 的边界划分。
6. 知识检索链路：DocumentSplitService、DataRetriever、CompositeStoreImpl、SearchKnowledgeNodeHandler。

换句话说，你可以同时从「RAG 链路」和「模型接入 / 工作流 / 异步调度 / 容器化 / 模块化」两个角度讲项目。

## 6. 面试官通常会从哪些层次往下追问

常见追问链路如下：

1. 先问你做过什么 AI 项目。
2. 再问你怎么接入模型，为什么选这个模型。
3. 再问你 Prompt、结构化输出、工具调用怎么设计。
4. 再问 RAG 怎么做：切分、检索、重排、评估。
5. 再问你 Agent 和工作流怎么拆，什么时候不用 Agent。
6. 再问你怎么评估效果、怎么观察成本、怎么保障安全。
7. 最后问你如何上线、如何扩容、如何处理故障。

这套文档就是按照这条面试追问链设计的。

## 7. 自检清单：如果这些点答不稳，就说明还没准备完

你至少应该能稳定说清以下问题：

1. Transformer 为什么适合大模型。
2. temperature、top_p、max_tokens 分别影响什么。
3. 预训练、SFT、RLHF、DPO 的差别。
4. 为什么很多 AI 应用不一定要自己微调模型。
5. 量化、LoRA、蒸馏分别解决什么问题。
6. 云模型、本地模型、开源模型、闭源模型怎么选。
7. Java 里为什么常用 Spring AI 或 LangChain4j。
8. 结构化输出为什么比纯文本解析更稳。
9. Tool Calling 和 MCP 是什么关系。
10. Workflow 和 Agent 分别适合什么场景。
11. RAG 的核心瓶颈为什么通常在检索侧。
12. 怎样做流式输出和会话状态管理。
13. 怎样做超时、重试、限流、降级和熔断。
14. 怎样做效果评估、在线监控和成本治理。
15. 怎样防 Prompt Injection 和越权工具调用。
16. 怎样把一个 AI Demo 上线成可运维的生产系统。

如果上面这些问题你都能讲清楚，说明你已经不是只会“调用模型 API”的准备状态了。

## 8. 各文档怎么配合

建议组合方式：

- 面试「AI 应用工程师 / Java AI 开发 / 大模型应用开发」：先用 `01 + 02 + 04` 建立通识框架。
- 岗位明确强调知识库问答、企业知识助手：重点补 `03`，项目表达看 `06`。
- 岗位要求 Agent、工作流、工具调用、自动化编排：`04` 优先级最高，`05` 补招聘关键词。
- 临场前 30 分钟：只看速记版 + 口语版。

## 9. 最后提醒

真正面试里，面试官不会按教科书顺序提问，而是经常把“模型能力”“工程实现”“项目取舍”“生产治理”混在一起问。所以准备时不要只背概念定义，更要练下面两种表达：

1. 定义 + 适用场景 + 代价。
2. 概念 + 你在项目里怎么做 + 为什么这么做。

后面的主文档就是按这种答法展开的。
